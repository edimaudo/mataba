# Mataba 2.9.2

Mataba is a Canadian contract-review application. The application server is **Python + FastAPI**. The browser interface is **HTML, vanilla CSS and TypeScript**. **Firebase AI Logic** is the Gemini integration.

There is one Python application. There is no `backend/` directory, no separate Node application server, and no Firebase Hosting requirement.

## Project structure

mataba/

The `app/` directory is the Python application package. It is not a second service. The Vercel entry point is `app/main.py`, which exports the FastAPI instance named `app`.

## Contract input methods

Contract review supports two input methods:

- **Upload document:** PDF, DOCX or TXT. PDF.js extracts selectable PDF text page by page in the browser. Mammoth extracts DOCX text in the browser. Explicit DOCX page breaks are preserved when present; otherwise the app records a section without inventing page numbers. Scanned/image-only PDFs are not OCR-processed in this release.
- **Paste text:** Users can paste contract text directly. Mataba wraps it as a local TXT document and sends it through the same extraction, local PII redaction, manual confirmation, evidence indexing and contract-analysis workflow as an uploaded file. The original pasted text is not sent to cloud inference; only the user-reviewed sanitized text is.

## Independent Legal Q&A

The Legal Q&A form includes a **Type of law** dropdown. The only available category in this release is **Employment law**. Jurisdiction can be federal, provincial/territorial or municipal. Municipal selection requires the parent province/territory and a municipality name. The backend supports a curated municipal source registry keyed by parent jurisdiction, municipality and law type; only sources explicitly registered with official URLs are eligible for retrieval. No municipal employment-law sources are currently registered, so a municipal employment question uses the parent federal/provincial/territorial employment statute and displays the source level actually checked. It does not claim that the retrieved statute is a municipal bylaw. Additional law categories and municipal sources require their own official-source entries and tests.

## How requests flow

```text
Browser: HTML + CSS + compiled TypeScript
                |
                | same-origin /api requests
                v
         Python FastAPI (app/main.py)
                |
                v
          Firebase AI Logic
                |
                v
         Gemini model response
```

FastAPI handles authentication verification, request validation, application logic, Firebase AI Logic prompt-template calls, citation verification and report rules. Firebase AI Logic is the only cloud Gemini integration. The browser Firebase SDK is retained only where the browser needs it (Firebase sign-in, App Check token, IndexedDB-backed UI persistence and Gemini Nano on-device inference).

## Why `frontend/package.json` remains

Browsers do not execute TypeScript directly. The TypeScript is compiled to browser JavaScript at build time. `frontend/package.json` lists browser libraries (Firebase Web SDK, PDF.js, Mammoth, Dexie and fflate) and the esbuild compiler. It does not contain an application server or dev-server command. Node/npm are only used during the build to obtain JavaScript ecosystem packages; the deployed application runs on Python FastAPI.

## Local setup

### 1. Create the Python environment

```bash
python -m venv .venv

# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
# .venv\\Scripts\\Activate.ps1

pip install -r requirements-dev.txt
```

### 2. Install browser libraries once

```bash
npm install --prefix frontend
```

This is a build-time dependency step only. It does not start Node or a second server.

### 3. Configure the Firebase project

Copy `.env.example` to `.env` and set the Firebase project ID, Web API key, Web App ID and server credentials. For local development, Application Default Credentials can be used with:

```bash
gcloud auth application-default login
```

For Vercel, put the base64-encoded service-account JSON into the `GOOGLE_SERVICE_ACCOUNT_JSON_BASE64` environment variable. Never commit service-account credentials or place them in the frontend configuration.

Keep `FIREBASE_AI_LOGIC_PROVISIONED_THROUGHPUT_ENABLED=false` until the client's Firebase AI Logic model, Montréal location and Provisioned Throughput configuration have been confirmed.

### 4. Build and run with Python

```bash
python scripts/dev.py
```

Open `http://127.0.0.1:8080`.

To build only:

```bash
python scripts/build.py
```

To run FastAPI directly after building:

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8080
```

## Vercel deployment

The project includes a root-level `vercel.json`. It configures:

- FastAPI's `app/main.py` as the Python function entry point (Vercel also recognizes this layout automatically).
- Vercel Function execution in Montréal (`yul1`).
- The TypeScript/static build command.
- Inclusion of Firebase AI Logic prompt templates and generated public assets in the function bundle.
- Exclusion of tests and development-only source files from the deployed function.
- No-store caching for API responses and safe default response headers.

### Configure the Vercel project

1. Push this repository to the client's Git provider.
2. In Vercel, select **Add New → Project** and import the repository.
3. Keep the project root at the repository root. Do not set `backend/` or `frontend/` as the Vercel root directory.
4. Vercel detects the FastAPI application at `app/main.py`.
5. Add the environment variables listed in `.env.example` in Vercel Project Settings. Add `GOOGLE_SERVICE_ACCOUNT_JSON_BASE64` as a sensitive variable.
6. Confirm the Function Region is Montréal (`yul1`). `vercel.json` already sets this region.
7. Deploy a Preview first. Verify `/`, `/qa`, a genuine HTTP 404 for an unknown page, `/api/health`, Firebase Authentication, App Check, official-law retrieval, and a staging Firebase AI Logic call using the legal Q&A template.
8. Promote to Production only after the Canadian processing and privacy acceptance checks pass.

Vercel's current FastAPI runtime supports `app/main.py` and automatically serves files in the root `public/` directory via its CDN. The project uses `vercel.json` for explicit build, region, function-file and header configuration. Firebase Hosting is not used.

### Deploy from the command line

Install and authenticate the Vercel CLI separately, then from the project root:

```bash
vercel link
vercel deploy
```

When the Preview passes acceptance tests:

```bash
vercel deploy --prod
```

The Vercel CLI is a deployment tool; it is not part of Mataba's runtime.

See [docs/VERCEL_DEPLOYMENT.md](docs/VERCEL_DEPLOYMENT.md) for the deployment checklist and service-account setup.

## Phase preservation

The flattening of the Python source package and the addition of Vercel deployment configuration do not change the implemented product requirements:

- Phase 1: Firebase AI Logic server prompt templates, structured responses, Canadian region validation and fail-closed behavior.
- Phase 2: browser document extraction, local PII detection/redaction, encrypted IndexedDB PII vault and evidence metadata.
- Phase 3: contract analysis, source citation verification, lawyer-style report and gated HR report sections.
- Phase 4: remains excluded, as requested.
- Phase 5: Firebase ID token/App Check checks, request size and rate limits, residual PII guard, Firestore/Storage rules and account deletion sequence.
- Phase 6: English/French UI, keyboard/focus behavior, responsive navigation, light/dark theme, font scaling and accessibility checks.

## Deployment and compliance limitations

Vercel region selection controls where the FastAPI Function executes; it does not, by itself, prove every downstream processor is in Canada. Firebase AI Logic model location/consumption mode must be independently confirmed. Static frontend files are delivered through Vercel's global CDN; no contract text or personal contract content is placed in those static files. Live Firebase AI Logic, App Check, model-region and end-to-end acceptance tests must be run against the client's staging project before production.

## Standalone legal Q&A and custom 404

Mataba includes an independent `/qa` page for questions about Canadian employment standards and labour law. A contract or uploaded document is **not** required. The user selects a federal, provincial/territorial or municipal scope. Municipal scope captures the municipality and its parent province/territory. The source resolver prefers a matching, explicitly registered official municipal source for the selected law type; otherwise, the current Employment law release retrieves the parent jurisdiction's employment/labour statute and identifies that source level. Answers include verifiable excerpts, links to official legislation and a general-information disclaimer.

The current Q&A scope is employment standards and labour legislation only. Federal Q&A is intended for federally regulated workplaces. The statutory registry includes one principal employment/labour statute for Canada and each province/territory. The municipal registry is implemented but has no employment-law source entries in this release. A municipal selection therefore adds local context but does not establish municipal-law coverage: unless a matching official municipal source is registered, Mataba uses and labels the parent-level employment statute. The corpus is not yet complete for every regulation, municipal bylaw or other legal domain. If supplied passages do not support an answer, Mataba returns an insufficient-evidence response rather than guessing. Questions are checked for residual personal identifiers and blocked when detected. Firebase Authentication and App Check are required as for the other cloud AI workflows.

The custom bilingual not-found page lives at `frontend/404.html`. `scripts/build.py` copies it to `public/404.html`; FastAPI returns it with HTTP 404 for unknown browser routes. Missing JavaScript/CSS/image/worker assets return a normal 404 response, not the HTML page.

### Q&A prompt setup

Create and lock the Firebase AI Logic server prompt template described in `firebase/ai_logic_templates/legal-qa.prompt`. Its template ID must match `FIREBASE_AI_LEGAL_QA_TEMPLATE_ID` (default `mataba-legal-qa-v1`). The Q&A endpoint retrieves the official legislation itself and places only the ranked excerpts in the prompt; callers cannot supply a URL or replace the trusted source registry.
